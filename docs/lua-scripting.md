# Lua scripting

Put server Lua files in a resource directory and list them with `server_script` in `fxmanifest.lua`. Each resource runs in a separate worker process with a Lua 5.4 state shared by that resource's server/shared scripts. Available APIs include `RegisterCommand`, `RegisterNetEvent`, `AddEventHandler`, `TriggerEvent`, `TriggerClientEvent`, `TriggerServerEvent`, and `GetPlayerName`. Local events and commands work in the resource worker; network calls explicitly fail because no network adapter is installed. Client execution, Wait scheduling, character/house APIs, and persistence are not implemented yet.

Local events are currently scoped to a single resource worker. A cross-resource event broker is a follow-up; server commands are registered with the host and routed back to the owning worker.

The runtime removes `os`, `io`, `package`, `debug`, `coroutine`, `dofile`, `loadfile`, `require`, `collectgarbage`, `pcall`, `xpcall`, and the NLua CLR bridge before executing resource code. A debug count hook enforces a 2 million instruction budget per script call by default, and script source is limited to 256 KiB. The parent terminates workers on request timeout or when private memory exceeds its configured limit (512 MiB by default). Workers run as the server's OS user, so this remains a process boundary rather than a restricted operating-system sandbox. Removing protected calls is intentional so scripts cannot catch and ignore the instruction-budget hook error.
