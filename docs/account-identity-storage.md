# Central Account Identity Storage

## Scope

The first central-account implementation slice adds durable account records and ownership-safe external identity links. It is deliberately not an authentication service: it does not issue browser sessions, validate Discord/Steam/Epic callbacks, or expose public HTTP endpoints.

## Data model

- `HogwartsAccount`: server-generated GUID, display name, creation timestamp.
- `ExternalAccountLink`: owning account GUID, provider enum (Discord, Steam, Epic Games), stable provider subject, optional provider display label, link timestamp.
- No email, password, access token, refresh token, authorization code, avatar URL, or provider secret is persisted.

## Store behavior

`JsonAccountIdentityStore` is a single-process JSON persistence adapter. It serializes operations within one store instance and writes through a temporary file followed by same-directory replacement. Corrupt or unsupported data is surfaced as an error rather than silently reset.

The store enforces:

- Account IDs are generated by the store.
- Only existing central accounts can receive external links.
- A provider subject can belong to only one HogwartsRP account.
- A HogwartsRP account can have at most one linked identity per provider.
- Repeating the exact same link for the same account is idempotent.
- Unlinking is scoped to the specified account and provider.
- Provider subject values must be supplied by a future server-side provider verifier. They are not trusted if submitted directly by a browser.

## Trust boundary

Only trusted server-side code may call `LinkVerifiedIdentityAsync`, and only after validating the provider's response and the one-time state bound to the authenticated central account session. No route currently calls this method. The method name and documentation intentionally make the verification precondition explicit.

The existing per-game-server OIDC join identity is not automatically a central account. A future central sign-in service must establish the central account session before browser account linking can be enabled.

## Deployment limitation

The JSON adapter is for local development and single-process use only. It is not safe for multiple service instances sharing the same file and is not a substitute for a transactional database, backup plan, or production secret-management system. A database-backed adapter and migration strategy are required before horizontal scaling or production account linking.

## Tests

The server test suite covers persistence across store instances, provider-subject uniqueness, one-link-per-provider, idempotent repeat linking, account-scoped unlinking, unknown account rejection, invalid subject rejection, and preservation of corrupt data.
